# 判断の受信箱

判断待ちと判断済みを行き来できる、ローカル専用の UI モック。依存追加・ビルド・外部通信は不要です。

## 起動

このディレクトリで実行します。

```sh
python3 -m http.server 4317 --bind 127.0.0.1
```

ブラウザーで http://127.0.0.1:4317 を開きます。停止は `Ctrl+C` です。

## 試せる操作

- 判断待ち 3 件と判断済み 1 件の一覧切り替え
- 「すぐ判断」「通常」「あとでよい」の絞り込みと、優先度順・受付順の表示
- 候補の選択、任意メモ、判断の確定、次の案件への移動
- 「あとで判断する」で判断待ちに残して次の案件へ移動
- 判断済みの回答・メモ・判断時刻・後続処理状態の確認
- 再読み込み後の回答保持、デモの回答だけの初期化

## 制限

案件は固定の 4 件です。確定した判断は「処理待ち」になり、初期の判断済み案件は「対応中」です。後続処理の「処理待ち / 対応中 / 完了」は表示用の状態で、実際の作業は実行しません。実キュー、バックエンド、外部サービスへの接続や送信はありません。

回答はブラウザーの `localStorage` の `decision-inbox-demo:v1` だけに保存します。同じブラウザー・同じ配信元で保持され、別の端末とは共有しません。メモに機密情報を入力しないでください。保存できない場合は判断を確定せずエラーを表示し、保存済みデータを読み込めない場合は上書きを防ぐため確定を止めます。初期化はこのキーだけを削除します。

候補やメモの下書きはページを開いている間だけ保持されます。再読み込みで未確定の入力は失われます。複数タブでの同時編集・同期は対象外のため、1 タブで使用してください。案件の選択は一覧操作・判断確定・あとで判断する操作のときだけ変わり、自動更新はありません。

`index.html`、`style.css`、`app.js` が画面の全体です。新しいブラウザーを想定しています。

## 再検証と再開

サーバーの起動後、インストール済みの `agent-browser` を使って実行します。アプリ自体に依存の追加はありません。

```sh
node --check app.js
bash tests/self-check.sh
```

別ポートでは `bash tests/self-check.sh http://127.0.0.1:56366` のように URL を渡します。専用の独立ブラウザーセッションで候補選択・確定・保存失敗・再読み込み・優先度・保留・初期化・破損データ保護・モバイル配置を検証します。デモ回答は退避し、終了時に復元します。他の保存キーを消しません。

再開時はこの README の起動と検証から進められます。
